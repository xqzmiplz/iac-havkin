# hw-01: стенд для показа продукта

## Что это

Стенд для демонстрации продукта клиентам. Поднимается перед показом одной командой и удаляется сразу после, поэтому между показами не стоит денег. Переживает отказ одной машины: балансировщик перестаёт направлять трафик на неисправную машину, клиент ошибки не видит.

## Состав стенда

| Компонент | Имя | Зона | Примечание |
|---|---|---|---|
| Сеть | havkin-02-net | | своя, не default |
| Подсеть A | havkin-02-subnet-a | ru-central1-b | 10.12.1.0/24 |
| Подсеть B | havkin-02-subnet-b | ru-central1-d | 10.12.2.0/24 |
| Веб-серверы | havkin-02-web-1..N | A и B поочерёдно | публичный адрес, порт 8006 |
| Сервер приложения | havkin-02-app-1 | A | без публичного адреса |
| NAT-шлюз | havkin-02-nat | | выход в интернет для закрытой подсети |
| Таблица маршрутизации | havkin-02-rt | | привязана к подсети A |
| Балансировщик | havkin-02-lb | | принимает на 80, раздаёт на 8006 |

Сервер приложения не имеет публичного адреса и недоступен из интернета. Выход наружу (нужен cloud-init для установки nginx) обеспечивает NAT-шлюз: исходящие соединения проходят, входящие снаружи нет. К серверу приложения можно обратиться только с веб-серверов по внутреннему адресу.

## Как движется трафик

Наружу смотрят только балансировщик и веб-серверы. Сервер приложения не имеет публичного адреса: обратиться к нему можно только с веб-серверов по внутренней сети. В интернет он выходит через NAT-шлюз, а входящие соединения снаружи невозможны.

| Откуда | Куда | Порт | Зачем |
|---|---|---|---|
| Клиент (интернет) | балансировщик `havkin-02-lb` | 80 | входная точка стенда, единственный адрес, который знает клиент |
| Балансировщик | веб-серверы `web-1..N` (обе зоны) | 8006 | раздача запросов, проверка состояния по HTTP |
| Веб-серверы | сервер приложения `app-1` | 8006 | обращение по внутреннему адресу, снаружи недоступно |
| Сервер приложения | интернет, через NAT-шлюз `havkin-02-nat` | любой (только исходящие) | установка nginx при первой загрузке |

## Требования

- установленный и настроенный `yc` (`yc config get folder-id`, `yc config get compute-default-zone`)
- утилиты `jq` и `envsubst`
- SSH-ключ `~/.ssh/id_ed25519.pub`
- запуск из корня репозитория

## Как поднять

```bash
bash hw-01/create.sh
```

Скрипт идемпотентный: перед созданием каждого ресурса проверяет его существование через `get` и пропускает существующие. Повторный запуск не падает и не создаёт дубликатов. Время развёртывания: около 3,5 минут. После завершения скрипта cloud-init на машинах может ещё дорабатывать около минуты, поэтому `check.sh` сразу после создания иногда покажет ✗.

### Параметры

Приоритет: аргумент командной строки, затем переменная окружения, затем значение по умолчанию из варианта.

| Параметр | Аргумент | Переменная окружения | По умолчанию |
|---|---|---|---|
| число веб-серверов | `--web-count N` | `WEB_COUNT` | 3 |
| порт сервиса | `--port N` | `APP_PORT` | 8006 |
| слово на странице | `--word TEXT` | `GREETING` | cloudlab |

```bash
bash hw-01/create.sh --web-count 4
WEB_COUNT=5 bash hw-01/create.sh
```

## Как проверить

```bash
bash hw-01/check.sh
echo $?
```

Три проверки, по строке на каждую:

1. Балансировщик отвечает кодом 200.
2. Ответы приходят от всех веб-серверов стенда (число ответивших машин сравнивается с общим числом веб-серверов в облаке).
3. Сервер приложения доступен с `web-1` по внутреннему адресу.

Код возврата: `0`, если прошли все три проверки, `1`, если не прошла хотя бы одна.

Пример вывода на исправном стенде:

```
✓ балансировщик отвечает: 200
✓ ответили машины: havkin-02-web-1,havkin-02-web-2,havkin-02-web-3
✓ сервер приложения доступен с havkin-02-web-1
```

### Проверка отказа машины

```bash
ssh student@<внешний IP web-1> "sudo systemctl stop nginx"
sleep 10
bash hw-01/check.sh; echo $?
ssh student@<внешний IP web-1> "sudo systemctl start nginx"
```

При остановленном nginx первая строка остаётся ✓ (балансировщик отвечает 200: сервис для клиента жив), вторая становится ✗ («ответили не все машины»), код возврата 1. Это правильное поведение: сервис работает, но стенд деградировал, и при отказе ещё одной машины клиент увидит ошибку.

## Как снести

```bash
bash hw-01/destroy.sh
```

Скрипт находит ресурсы по префиксу `havkin-02` и удаляет их в порядке, обратном созданию: балансировщик, целевая группа, машины, отвязка таблицы маршрутизации от подсети, таблица и NAT-шлюз, подсети, сеть. Не падает, если часть ресурсов уже удалена. Время сноса: около 3 минут.

После уборки проверьте отдельно, что ничего не осталось (диски и адреса тарифицируются даже без машин):

```bash
yc compute instance list
yc compute disk list
yc vpc address list
yc vpc network list
yc load-balancer network-load-balancer list
```

## Стоимость

Цена часа работы стенда (3 веб-сервера, сервер приложения, балансировщик, NAT-шлюз, публичные адреса): около 2,93 ₽. Стенд на один показ (2 часа плюс 6,5 минут на подъём и снос) стоит около 6,19 ₽. Постоянная работа обходится примерно в 2 112,70 ₽ в месяц, по показам (13 в месяц) выходит около 80,5 ₽, экономия около 2 032 ₽ в месяц. Подробный расчёт приведён в отчёте.

## Если check.sh вернул ошибку

| Что показал check.sh | Что проверить |
|---|---|
| ✗ балансировщик не найден | стенд не поднят или уже снесён: `yc load-balancer network-load-balancer list`, при необходимости `bash hw-01/create.sh` |
| ✗ балансировщик отвечает: не 200 | статус балансировщика (`yc load-balancer network-load-balancer get --name havkin-02-lb`), состояние целевой группы, прошли ли health check. Если машины вечно UNHEALTHY, проверьте, что группа безопасности сети разрешает трафик с диапазонов `198.18.235.0/24` и `198.18.248.0/24` на порт 8006 |
| ✗ ответили не все машины | на какой-то машине не работает nginx или не завершился cloud-init. Проверьте `curl http://<IP машины>:8006` для каждой, при необходимости `ssh` и `sudo systemctl status nginx`. Если стенд только что создан, подождите минуту и повторите |
| ✗ ответила только одна машина | то же самое, но осталась одна живая машина: срочно восстановите остальные |
| ✗ сервер приложения недоступен с web-1 | проверьте, что app-1 создан и получил внутренний адрес, что cloud-init на нём отработал (для этого нужен NAT: `yc vpc route-table get --name havkin-02-rt`, `yc vpc subnet get --name havkin-02-subnet-a`, поле `route_table_id`), и что группа безопасности пропускает внутренний трафик на порт 8006 |
